# 共用仲裁双字写回筛选

研究候选沿用 4×32 FIFO 门控版的数值、输入装载、计算和私有 SRAM。模型将结果写回纳入 CPU／DMA 共用仲裁，在一次 DMA 写授权中提交一对 32 位字。提交版为 T＋R＋B。

| 12 项口径 | FIFO 门控对照模型 | 共用仲裁双字写回模型 |
|---|---:|---:|
| 每项冷窗 | 14,344 拍 | 14,984 拍 |
| 总周期 | 172,128 拍 | 179,808 拍 |
| 按 150 MHz 折算的吞吐 | 10,457.33 tasks/s | 10,010.68 tasks/s |
| 首发射 | 826 | 826 |
| 最后物理写提交 | 14,343 | 14,983 |
| 最后 ACK | 14,344 | 14,984 |
| 结果槽峰值 | 5/8 | 5/8 |
| 输出信用峰值 | 34/34 字 | 34/34 字 |

对照模型逐项匹配 FIFO 版 12 份原生门级日志中的冷窗、最后物理提交和 ACK。共用仲裁模型每项比对照多 640 拍，距 10K 线每项余 16 拍，12 项合计余 192 拍。相对 T＋R＋B 实测的 33,262 拍，模型冷窗缩短约 55%。

## 物理访问和数据检查

- 每项完成 11,680 个主机有效装载字、10 个控制及守卫提交、11,680 个 DMA 读字、6,336 笔双字提交和 6,336 笔 ACK。对应 12,672 个物理结果字、25,344 个逐位一致的输出。两个结果字同拍提交，下一拍一次 ACK 退休。最后一次写实际提交后释放该槽。
- 结果窗口内交换相对字地址 bit 12 和 bit 0。整个 64 KiB 窗口的映射为自逆双射。每个 64 位条目都落在同一槽的连续逻辑地址，物理写只使用 bank 4/5 或 6/7，每拍没有重复 bank 访问。模型在物理地址保存字值，再按 CPU 使用的逻辑地址映射读回并核对全部输出。
- 代表项有 5,880 个 DMA 读拍，其中 5,800 个双读拍。6,336 个写拍中有 6,132 个可接续上一笔写 ACK。读转写停 64 拍，写转读停 59 拍。主机写和源 DMA 读有 4,721 拍重叠，其中 4,638 拍为双读和双主机写。DMA 写拍不与源读或主机写重叠。
- 输入前缀等待从 31 拍增至 712 拍，权重页等待从 1,200 拍增至 1,226 拍。算术发射仍为 12,800 拍，结果槽等待计数为零。前缀等待是模型中最大的新增发射停顿，换向计数与计算等待有时间重叠。

## 模型口径与后续验收

原模型冻结已观测 E203 启动和共享 CPU 请求时刻。候选沿用该启动输入，逐拍自行计算载入资格、仲裁方向、同步返回、输出信用和物理写入。按下一拍 ACK 可接收、读写换向有一个空拍建模。CPU 地址掩码、实际共享端口和 ACK 反压仍需通过候选 RTL 及整机复核。10K 余量很小，面积、150 MHz 时序、功率和能耗待候选实测。

本地已存答疑明确允许在原 SoC 硬件框架内使用 DMA。模型阶段核对 QQ，组委会回复仍未明确覆盖双 bank 写入及透明地址交错。随后用户授权按该假设进行独立 RTL 试验，提交版保持 T＋R＋B。

## 本机 RTL 复核

`python -B scripts/trb_4x32_shared_pair/build.py` 生成独立 SoC，`python -B scripts/trb_4x32_shared_pair/local_core.py` 复现本机测试。12 项连续冷任务均核对 25,344 个结果、11,680 个源 DMA 读字和 12,672 个物理结果写字。每笔写验证两个目标 bank 的写使能、地址、掩码和数据。代表项加入 256 笔 CPU 争用及 DMA 写 ACK 背压，观察到 2,534 拍写请求受阻及 1,464 拍 ACK 受阻；后续 CPU 对结果窗口的掩码写和读回通过。

本机核心台架为每项 15,008 拍，首发射在第 850 拍，较模型均晚 24 拍，符合该台架已知启动偏移。整机吞吐需要用原生 E203 的实际装载和调度重新核对。

## 原生 E203 RTL 结果

真实 E203、VCS 和原厂 SRAM 仿真模型的 12 项均通过。每项完整冷窗 **14,984 拍**，最后物理写提交 **14,983**，最后 ACK **14,984**。12 项合计 **179,808 拍**，以 150 MHz 折算 **10,010.6780565937 tasks/s**。每项核对 25,344 个结果、11,680 个 DMA 读字、12,672 个结果写入和对应 ACK 字数。原生日志和总表已回收到 `received/cpu-evidence`，CRC `6a288d44`，归档与展开文件逐字节一致。该数据对应 RTL 功能仿真和完整冷窗周期。

首次原生 VCS 要求 `result_q` 在使用前声明，已移动声明并复跑 VCS；数据通路不变。

## 最终网表时序与面积

原生 raw、hold、final 已生成。最终 SS/EMA2 网表通过 150 MHz，建立余量 **+0.655757 ns**、保持余量 **+0.144989 ns**，门控、电气及专项路径检查零违例。计分面积 **0.523447902 mm²**，比 FIFO 独立写口版多约 **0.001748258 mm²**。原生报告回收到 `received/timing-evidence`，CRC `32c45e26`。

后续证明启动曾因服务器缺少 `native_proofs.py` 退出。补齐原辅助脚本后，RTL 到 raw、raw 到 hold、hold 到 final 三段网表证明均通过，E203 RTL 仿真和综合结果均复用。

## 同一最终网表的整机功耗

12 项真实 E203 门级回放、冷窗 SAIF 和 PrimeTime PX averaged 功耗测量均完成。最终网表标记为 `opt_ffn_trb_4x32_shared_pair_final_ss_ema2`。12 项共 **179,808 拍**，吞吐 **10,010.6780565937 tasks/s**，整机加权平均功率 **61.06348330614404 mW**，平均单任务能耗 **6.099834892395083 μJ**，计分面积 **0.523447902 mm²**。

相对 FIFO 独立写口版，平均功率减少 **2.029%**，冷窗延长 640 拍，平均单任务能耗增加 **2.342%**。12 项功耗结果、门级回放回执及三段证明汇总已回收到 `received/power-evidence`，CRC `447e34c6`。提交版仍为 T＋R＋B。
